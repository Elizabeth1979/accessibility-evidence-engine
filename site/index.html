On a real app

A photo-album app, 130 tests, one import changed

albums-studio is a React app. Its tests import AEE's test instead of Playwright's, and its CI posts the result as a comment without ever failing the build.

  • 2 contrast failures the app's own axe checks missed: a button's hover colour and the line under a failed upload
  • 114 of 118 tests' pages decided, pass or fail; the other 4 are listed for a person to check
  • 1.56 the Playwright version the app had, left as it was

Get started

Three changes to a Playwright project

AEE uses your project's Playwright, version 1.50 or later.

  1. Install it

    Install the packages from the latest release, as the install guide shows.

  2. Swap one import

    import { test, expect } from "@aee/cli/test";

    Every page a test opens is then checked. Read the Playwright guide

  3. Comment on pull requests

    Run the end-to-end step through the AEE Action for one comment on each pull request. Set up the Action

Trust requires boundaries

What a passing report does—and does not—mean

AEE can support

  • Repeatable investigation around selected interactions
  • Evidence-linked triage and release-policy decisions
  • Explicit unknown and unsupported results

AEE cannot certify

  • Complete WCAG conformance
  • All assistive-technology experiences
  • That captured artifacts are safe to share without review
