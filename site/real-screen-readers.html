No Windows computer needed

How a run works

GitHub lends a Windows computer for each run, free for public projects. Nobody sits at it: Guidepup presses the keys and writes down what NVDA says.

  1. You press RunIn GitHub, from any device. It also runs by itself (see below).
  2. GitHub starts WindowsA fresh Windows computer in GitHub's data centre, for about 15 minutes.
  3. NVDA reads the pageNVDA 2026.2 reads the test lab page in Chrome with the Down Arrow, the way a user would. AEE's reader reads the same page.
  4. You get the evidenceNVDA's words, AEE's words, the side-by-side page and the video.

Your choices

Any or all, each time you run it

  • When it runs: all three ways

    By itself when a pull request changes the reader code, by itself once a week (that catches a new Chrome), and whenever you press Run.

  • Which readers: tick any or all

    NVDA is ticked by default. Tick VoiceOver as well and GitHub also starts a Mac. The comparison gets a column for each reader that ran.

  • Retries: you pick the number

    A retry never changes what a reader says, only whether the run gets going, and the run page says when one was needed.

Precedent

Where each setup step comes from

Every step copies how Guidepup's own tests run screen readers on GitHub. No safety setting is switched off.

Only the public test lab page is read. The run takes no page address, so no private page's words can reach GitHub's public logs.

Not in this plan

JAWS

JAWS can be driven automatically, but it needs a paid licence and a different tool from Guidepup. Guidepup drives NVDA, VoiceOver and Orca only (guidepup#125 is still open).

JAWS has a built-in Remote Command Server that speaks W3C's standard protocol for driving screen readers. W3C's own screen-reader test project already uses it to run JAWS on GitHub's Windows computers (aria-at-gh-actions-helper), with a JAWS licence kept secret. For AEE, the first step is asking Vispero whether their licence allows it.
